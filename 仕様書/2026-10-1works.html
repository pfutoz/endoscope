1. 改修の背景と目的

従来、医療安全アラートスキャン判定機能（予約備考の確定タグや電子カルテメモから抗血栓薬・アレルギー・感染症・風邪症状を検出・保存する機能）は、各親画面（month_schedule.php、month_matrix_v2.php、progress_monitor.php、schedule_note.php）内に medical_alert_modal_inc.php をインクルードし、700行を超えるインラインHTML・CSS・JSをページ内部に直接展開する構成となっていました。

この方式には以下の課題が存在していました：

  • 親画面のDOM構造が肥大化し、スクリプトやスタイルが画面全体と競合するリスクがあった。
  • 予約登録・編集画面（modal_edit.php）のようにNative <dialog> + <iframe> でサンドボックス化されておらず、単体での直接URLアクセスや独立テストが困難だった。

本改修では、ユーザー要望である「アラートスキャンを別ファイルにしたい。modal_edit.phpと同じような動き」に基づき、スキャンUIおよびロジックを独立したPHPファイル（modal_medical_alert.php）へ完全分離し、modal_edit.php と同一のNative Dialog + iframe + postMessage連携アーキテクチャへと刷新しました。

2. modal_edit.php と同一アーキテクチャ設計

予約モーダル（modal_edit.php）で確立されたモダンかつ堅牢なiframeモーダル連携パターンを医療安全アラートにも完全適用しました。

💡
完全サンドボックス化 ＆ 双方向 postMessage 連携
モーダル内部は親画面から独立したDOM空間で動作し、閉じる・保存完了のアクションを window.parent.postMessage() で安全に伝達。親画面はメッセージを受信してダイアログを自動消去し、画面を同期リロードします。 
【アーキテクチャ構成図】

親画面 (month_schedule / month_matrix_v2 / progress_monitor / schedule_note)
   │
   ├─ openMedicalAlertScanModal({date: '2026-10-01', dept: 'PROCT'})
   │     │
   │     ▼
   │  [Native <dialog id="modalMedicalAlertRunnerDialog">]
   │     └─ <iframe src="modal_medical_alert.php?date=2026-10-01&dept=PROCT">
   │           │
   │           ▼ (独立ページ内で安全にレンダリング＆スキャンAPI実行)
   │        [modal_medical_alert.php]
   │           ├─ 全選択 / 全解除 / 再スキャン
   │           ├─ MALL3電子カルテビューアー連携 (別タブ)
   │           └─ 「この内容でアラートを反映・保存」クリック
   │                 │
   │                 ▼
   │              action_medical_alert.php (DB保存成功)
   │                 │
   │                 ▼
   │              window.parent.postMessage({ type: 'medical_alert_saved' }, '*')
   │
   ▼
親画面の message リスナーが受信
   ├─ dialog.close() でアニメーション終了
   └─ トースト通知表示 ＆ 親画面最新状態へ自動リロード！

3. 新規実装・分離コンポーネント詳細

① 独立単体画面: modal_medical_alert.php の新設

単独で完結するHTML5ページとして新規作成。URLクエリ（date, dept, year, month, schedule_ids）を受け取り、ロードと同時に action_medical_alert.php?action=scan を非同期フェッチして候補患者を描画します。

  • ヘッダー: エメラルドグリーン×ティールグラデーション、閉じるボタン（✕）、Escキー連携。
  • ツールバー: 検出サマリー（注意患者数バッジ）、一括「全選択」「全解除」、非同期「🔄 再スキャン」ボタン。
  • 患者カード: 確定タグ付き強調表示（オレンジ帯）、MALL3電子カルテビューアー直通リンク（別タブ）、検出根拠スニペット（ハイライト付き）、4つのフラグチェックボックス。
  • フッター: ヒント、キャンセル、二重送信防止ロック付き「この内容でアラートを反映・保存」ボタン。

② 共通ランナー: medical_alert_modal_inc.php の超軽量化

従来の700行超に及ぶ巨大インラインDOM・描画ロジックをすべて撤去し、以下の2つの責務に特化した超軽量インクルードに刷新しました：

  1. 親画面のカレンダーセルや一覧テーブルで必要なアラートバッジ・チップ表示用共通CSS（.chip-anti, .chip-allergy 等）。
  2. openMedicalAlertScanModal(options) を定義し、動的に <dialog> と <iframe> を生成して modal_medical_alert.php を呼び出すランナーロジック。

これにより、各親画面に記述されている include 'medical_alert_modal_inc.php'; や onclick="openMedicalAlertScanModal(...)" は一切書き換える必要がなく、完全な後方互換性を保ったまま即座に iframe モーダルへ昇華しました。

③ 統合スクリプト（assets/js/month_schedule.js 等）の postMessage 強化

month_schedule.js、month_schedule2.js、modal_edit_runner.js のグローバルメッセージリスナーに medical_alert_close および medical_alert_saved ハンドラを追加し、どの画面からでも安定してダイアログ消去とリロードが連動するよう多重防御を施しました。

4. 🌐 オンライン資格確認連携 ＆ 予約個別編集の手動任意照会

内視鏡検査における休薬事故防止や安全管理の精度を格段に引き上げるため、オンライン資格確認システム（薬剤情報・リスク患者判定API: api_onshi_yakuzai.php）との自動連携および予約個別編集画面（modal_edit.php）における任意照会機能を実装しました。

① 医療安全リスク判定体系の拡張（全7項目・2グループ編成）

従来の4項目から、内視鏡検査前後の全身管理・投薬判断に必須となる糖尿病薬、向精神薬・睡眠薬、NSAIDs消炎鎮痛薬の3大リスクを新設。画面上で目的別に即断できるよう2グループに整理しました。

グループ アラート項目 DBカラム 内視鏡検査における臨床的安全リスク・確認理由
Group 1: 🌐 オン資・薬剤リスク
他院処方歴の直近6ヶ月照会		 💊 抗血栓薬 has_antithrombotic バイアスピリン、イグザレルト、エリキュース、プラビックス等。生検・EMR・ポリペク時の出血対策（休薬プロトコル確認要）。
💉 糖尿病薬 has_diabetes 新設 インスリン、メトホルミン、SGLT2阻害薬、DPP-4等。検査前絶食時の低血糖発作・アシドーシス・脱水予防。
🧠 向精神薬・睡眠薬 has_psychotropic 新設 ベンゾジアゼピン系、オピオイド、抗うつ薬等。鎮静剤（ミダゾラム・プロポフォール等）使用時の呼吸抑制・相互作用注意。
💊 NSAIDs消炎鎮痛 has_nsaids 新設 ロキソニン、ボルタレン、カロナール等。胃十二指腸潰瘍・出血リスク、粘膜脆弱性・腎機能リスクの事前把握。
Group 2: 📋 カルテ・予約注意
電カル確定タグ＆メモ		 ⚠️ 局麻・アレルギー has_allergy キシロカイン等の局所麻酔薬や薬剤アレルギー既往。アナフィラキシー対策。
🔴 感染症注意 has_infection B型肝炎(HBV)、C型肝炎(HCV)、梅毒、HIV等。感染防御具着用・スコープ別系列洗浄・最終枠配置。
😷 風邪症状・発熱 has_cold_fever 当日有熱・呼吸器症状。検査延期・隔離動線判断。

② 高速バッチ照会（curl_multi 80ms）＆ 期間切替（直近6ヶ月 ⮂ 全期間）

action_medical_alert.php 側で、一覧対象の全患者IDを curl_multi を用いて並行非同期照会。30名の一括スキャンでも約150〜200ms以内に完了します。

モーダル上部ツールバーに「📅 処方期間（直近6ヶ月 / 全期間）」ドロップダウンを新設。休薬期間の長い薬剤や数年前の処方歴を確認したい場合、即座に全期間（months=0）へ切り替えて再スキャンできます。

③ 予約個別編集画面（modal_edit.php）の「🌐 オン資照会」＆「🛡️ 詳細判定」機能

🛡️
2つの選べるアプローチ（簡易オン資照会 ＆ リッチ詳細判定モーダル起動）
医療安全設定ボックス内に、用途に応じて選べる2つのアクションボタンを新設しました：
  • 【🌐 オン資照会】（即時簡易照会）: ボタン1つで非同期にオン資APIを問い合わせ、該当リスク薬を即座に推奨ON＆ヒント表示（画面遷移・モーダル展開なし）。
  • 【🛡️ 詳細判定】（modal_medical_alert.php 起動）: クリックすると当該患者の modal_medical_alert.php?patient_id=... が子モーダルとして開き、全処方歴・他院調剤薬局名・カルテメモ根拠をリッチに精査可能。保存すると親画面（modal_edit.php）の7項目チェックボックスへ自動同期反映されます。

④ 監査ログ（t_audit_log）と Undo（巻き戻し）の完全対応

予約保存時および一括判定保存時に、新設3項目（糖尿病・向精神薬・NSAIDs）の変更差分を [💉糖尿病薬: OFF→ON] のように日本語ラベルで監査ログに記録。直前取消や Undo 実行時にも restoreMedicalAlertFromAudit() により正確に元の状態へ復元されます。

⑤ 当日進捗ステータスモニターの空き枠・枠なし完全非表示化（実患者限定表示）

当日進捗ステータスモニター（progress_monitor.php / get_progress_data.php）において、現場の動線把握を最優先するため、予約のない空き枠や「※枠なし」設定レコードを完全非表示化しました。

  • APIクエリ（get_progress_data.php）の最適化: s.patient_name IS NOT NULL AND TRIM(s.patient_name) != '' AND s.patient_name NOT LIKE '%枠なし%' 条件を適用し、実患者が存在する予約のみを抽出。
  • サマリーバー正確集計: 本日合計（Total）や各ステータス人数（受付済、待機中、検査中等）のカウントから空き枠・枠なしが排除され、純粋な実来院患者数と完全一致。
  • フロントエンド（progress_monitor.php）の多重防御ガード: 高密度表およびタイルグリッド描画ループにおいて空き枠・枠なしをスキップし、ノイズのない視認性を実現。
