1. 改修背景と達成ゴール

本改修では、Modern Web 最適化版として開発を進めてきた month_schedule2.php の肥大化に伴うIDEフリーズや表示レスポンスの低下を解決するため、CSSおよびJavaScriptを完全に独立モジュールへ外出し分離しました。

5. 医師別予約件数バッジの安全同期（月ズレバグ解消）

カレンダー上部の医師別件数表示（例: 「哲也 2」「義智 16」）において、選択している日付（例: 9月28日）とカレンダー表示月（例: 10月）が異なる場合、$is_same_month === false の判定により $doctor_counts = [] と初期化され、強制的に全医師が「0件」と表示される不具合がありました。

解決策（安全同期ロジックの実装）

// month_schedule2.php (医師別予約件数集計の強化)
if ($is_same_month && isset($calendar[$day_of_month])) {
    $doctor_counts = $calendar[$day_of_month]['doctor_counts'] ?? [];
} else {
    // 選択日と表示月が異なる場合でも、選択日の予約一覧データ ($list_data) から正確に集計
    $doctor_counts = [];
    foreach ($list_data as $row_item) {
        if (empty($row_item['is_empty'])) {
            $dname = trim((string)($row_item['doctor_name'] ?? ''));
            if ($dname !== '') {
                $doctor_counts[$dname] = ($doctor_counts[$dname] ?? 0) + 1;
            }
        }
    }
}

これにより、カレンダーの月を前後させても、現在選択されている日付の実際の予約件数が常に正しくバッジに反映されます。

6. 折りたたみ・上下入替バグの根本解消（SyntaxError根絶）

「カレンダーを折りたたむ」および「上下入替」ボタンをクリックしても何も動作しないという重大な不具合が発生していました。

不具合の根本原因

🚨
Uncaught SyntaxError: Identifier 'currentScheduleDept' has already been declared
month_schedule2.php のインラインスクリプト（1965行目）で const currentScheduleDept = '...' を宣言しているにもかかわらず、外部JSファイル month_schedule2.js の222行目でも同名の const currentScheduleDept が宣言されていました。
ブラウザのJavaScriptエンジンは同一グローバルスコープでの const 再宣言を構文エラーとみなし、外部JSファイルのロード・解析を即座に中断していました。このため、ボタンに付与された関数やリスナーが一切実行されなくなっていました。

適用した根本対策

  1. グローバルスコープ変数の安全一元化: month_schedule2.php 側では window.currentScheduleDept = '...' として公開し、外部JS側でも var currentScheduleDept に変更して再宣言エラーを根絶。
  2. 関数のグローバル公開と二重バインド: window.toggleCalendar = toggleCalendar; および window.toggleLayoutOrder = toggleLayoutOrder; を明示的に設定。さらに HTML 上の onclick 属性だけでなく、DOMContentLoaded 内でボタン要素にイベントリスナーを直接バインドする二重安全設計を適用。
  3. 上下入れ替えDOM判定の安定化: 本番環境（month_schedule.php）で実績のある calWrapper.nextElementSibling === listWrapper による順序判定に復元。
  4. CSS非表示スタイルの強化: .calendar-wrapper.collapsed { display: none !important; } を指定し、カレンダーが確実に瞬時に折りたたまれるよう保証。
