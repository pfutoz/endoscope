1. 改修の背景と目的

従来の「枠なし」機能（t_endoscopy_schedule 内の ※枠なし レコード方式）と、新方式の「時間枠オーバーライド休止機能」（m2_waku_override.is_suspended）の間で画面判定ロジックの不整合が発生していました。

発生していた問題点:
  • オーバーライドで休止にした枠や、理由付きの枠なしデータが画面側で「空き枠」と誤判定され、［空き枠］・➕追加ボタン・🚫設定ボタンが重複して露出していた。
  • 備考欄に ***🚫枠なし[***枠なし***]*** などの内部ダミー記号がプレーンテキストとして露出していた。

本改修では、新旧どちらの枠なし・休止データであっても正しく赤背景（#fff1f2）、［枠なし設定済］、⭕復帰ボタン、および統一された赤バッジ備考を表示できるよう統合を行いました。

2. 実患者保護ガードの実装（重要インシデント対策）

検知されたインシデントと緊急対応:
休止枠判定（is_suspended）を単純に適用した際、2026-10-26 の TCF15:30~16:30 のように「時間枠に休止設定が存在するが、過去に実際の患者様の予約が既に入っている枠」において、確定予約患者様（鎌倉様・秋山様）の氏名が「［枠なし設定済］」で覆い隠され、備考欄が枠なしバッジに変換される表示不具合が発生しました。

直ちに本番DBの全レコードを調査し、データベース上の患者予約データは1文字の欠落もなく完全に安全（無傷）であることを実証しました。その上で、実患者様の予約が入っている行を絶対に枠なし判定しない「実患者保護ガード（Real Patient Guard）」を全画面・全APIに実装いたしました。 

// ★ 実患者保護ガード: 実患者様の予約行は絶対に枠なし扱いせず完全保護
$p_name_raw = trim((string)($row['patient_name'] ?? ''));
$is_real_patient = (!$is_empty && $p_name_raw !== '' && $p_name_raw !== '※枠なし' && $p_name_raw !== '※仮予約' && $p_name_raw !== '指定なし');

if ($is_real_patient) {
    // 実患者様の確定予約が存在する場合は、枠休止設定があっても絶対に枠なし化しない
    $is_no_waku = false;
} else {
    // 予約が入っていない空枠またはダミー枠なし予約のみ「枠なし」として処理
    $is_suspended_override = !empty($row['is_suspended']);
    $is_legacy_no_waku = (!$is_empty && (
        $p_name_raw === '※枠なし' ||
        mb_strpos($remarks_str, '枠なし') !== false ||
        mb_strpos($remarks_str, '休止') !== false
    ));
    $is_no_waku = ($is_suspended_override || $is_legacy_no_waku || !empty($row['is_no_waku']));
    if ($is_no_waku) {
        $is_empty = false;
    }
}

これにより、休止枠に実患者様の予約が存在する場合でも、患者名・患者ID・カルテリンク・年齢・生年月日・詳細な備考欄が100%通常通り正確に表示されるようになりました。
