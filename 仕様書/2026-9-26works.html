2予約編集モーダルにおける出勤例外医師の反映対応

📌 事象・課題の背景

検査枠マスターメンテナンス（slot_master_maintenance.php）の「出勤例外」タブにおいて、2026-11-14（土）に哲也先生の検査枠（GIF: 5, エコー: 2, TCF: 8 / 合計: 15） を登録した際、以下の乖離が発生していました。

  • 月間カレンダー（month_schedule.php）: 正常に「哲 🔵0/5 🟠0/2 🟢0/8」と枠数が反映され、日別セルにも青丸囲みバッジが表示される。
  • 予約編集モーダル（modal_edit.php）: 該当日の時間枠をクリックして予約編集モーダルを開くと、「担当医師」プルダウンに「哲也」が表示されず、担当医師として割り当てることができない。

🔍 原因の究明

原因の所在: 予約編集モーダルの医師選択肢を非同期取得する get_present_doctors.php の内部クエリにおいて、システム最優先テーブルである「出勤例外（m2_doctor_attendance）」の参照処理が抜け落ちていました。

modal_edit.php は、画面表示時および日付変更時に fetch('get_present_doctors.php?date=...&dept=...') を実行してプルダウンを再構築しています。しかし、従来の get_present_doctors.php では「基本の曜日パターン（m2_doctor_slot_pattern）」と「日別上書き（m2_doctor_daily_capacity_v2）」の2テーブルのみで出勤判定を行っており、曜日パターンに登録のない哲也先生が出勤判定から漏れていました。

🛠️ 実施した改修内容

get_present_doctors.php 内で独自実行していたSQLクエリを全面撤廃し、プロジェクト共通ライブラリ lib/slot_helper.php の getDoctorStatus() を呼び出すアーキテクチャに統一しました。

統一された出勤判定優先順位:
1. 出勤例外（m2_doctor_attendance） ← 最優先適用（枠数合計 > 0 なら出勤、0 なら休診）
2. 日別上書き（m2_doctor_daily_capacity_v2）
3. 曜日パターン（m2_doctor_slot_pattern）

3日別カレンダーメモ機能（t_daily_memo）の実装・連携

📌 目的と運用効果

カレンダー上の各日付セルに、医師の診療予定（例: 📝 哲診 義10 など）や休診連絡、日別の特記事項を直接メモとして登録・可視化できる機能です。紙の連絡票や別ファイルを参照することなく、カレンダーを一目見るだけで当日の体制や引き継ぎ事項を把握できます。

🗄️ データベース設計（t_daily_memo）

カラム名 型 制約 説明
id SERIAL PRIMARY KEY シーケンス主キー
department_code VARCHAR(20) NOT NULL 診療科コード（GASTRO / PROCT）
target_date DATE NOT NULL メモ対象日付（YYYY-MM-DD）
memo TEXT DEFAULT NULL メモ本文（連絡事項・医師割当等）
updated_at TIMESTAMP DEFAULT NOW() 最終更新日時

※ (department_code, target_date) の複合一意制約（UNIQUE）を付与し、同一科・同一日における重複登録を抑止（UPSERT対応）。

⚡ 高速化アーキテクチャ（N+1クエリ解消）

月間カレンダー（month_schedule.php）の描画において、1日ごとにSQLを発行すると最大35〜42回のクエリ遅延が発生します。これに対し、表示期間（前月末〜当月末）のメモを単一クエリで一括プリフェッチする方式を採用しました。

// 月間日別メモの一括プリフェッチ
$stmt_memo = $pdo->prepare("
    SELECT target_date::text, memo 
    FROM t_daily_memo 
    WHERE department_code = :dept 
      AND target_date >= :start_date 
      AND target_date <= :end_date
");
$stmt_memo->execute([':dept' => $dept, ':start_date' => $start_date_month, ':end_date' => $end_date_month]);
$month_daily_memo_cache = $stmt_memo->fetchAll(PDO::FETCH_KEY_PAIR);

各日付セル生成時は $month_daily_memo_cache[$date_str] によるインメモリ連想配列参照（計算量 O(1)）を行うため、データベース負荷および画面描画オーバーヘッドはほぼゼロです。

🖥️ UI/UX設計と画面連動

  • 日付セルバッジ表示（カレンダー部）: メモが存在する日は日付数字の横に .day-memo-badge（黄色背景）で 📝 メモ内容 を表示。セルクリックによる画面遷移と競合しないよう、バッジクリック時は event.stopPropagation() を介して直接編集モーダルを起動。
  • 選択日リスト側ヘッダー連動: 右側の選択日詳細エリアの見出し横にも現在のメモを表示し、クリックで再編集が可能。未登録時は「＋メモ追加」ボタンを表示。
  • 編集モーダル（dailyMemoModal）＆ 自動クリーンアップ: 非同期AJAX API（action=ajax_save_daily_memo）により、ページ遷移なしで保存・即時反映。空文字で保存された場合は DELETE クエリを発行して空レコードを自動消去する軽量最適化を実装。

4胃腸科GIF/TCF枠における実施場所デフォルト自動選択（modal_edit.php）

📌 改修の背景と運用ニーズ

胃腸科（GASTRO）の予約業務において、GIF枠およびTCF枠で予約登録を行う際、実施場所プルダウンはマスタ最上位の「内視鏡室」が選択される運用が大半を占めていました。しかし、従来は「-- 実施場所 --」（未選択）が初期値となっていたため、予約のたびに毎回プルダウンを開いて選択する操作負担が生じていました。

※なお、エコー枠については実施場所が多岐にわたるため、従来通り未選択をデフォルトとする仕様を維持することが求められました。

🛠️ 実装内容（初期値設定 ＆ 時間枠動的連動）

  • 新規予約画面読み込み時の初期判定（PHP）:
    URLパラメータまたは初期選択された時間枠名（$waku）に GIF または TCF が含まれる場合、実施場所（$curr_loc）にマスタの先頭アイテム（$exam_locations_master[0] ＝ 「内視鏡室」）を自動設定。エコー枠等の場合は空文字（未選択）を代入。
  • 時間枠変更イベントの動的連動（JavaScript: handleWakuChange）:
    新規予約画面（isNew）において、時間枠プルダウン（scheduled_time）を切り替えた際、選択枠が GIF または TCF なら実施場所プルダウンを自動的に先頭選択肢（locSelect.selectedIndex = 1）へ切り替え。エコー枠等へ切り替えた場合は未選択（locSelect.value = ''）に自動リセット。
  • 既存予約データの非破壊保護設計:
    既に保存・登録されている予約の編集画面（$schedule_id > 0 / !isNew）を開いた際には、本自動補完ロジックは作動せず、データベースに登録された実施場所を100%保持します。

function handleWakuChange(wakuName) {
    checkDuplicateAndLimits();
    if (!isNew) return;

    const dept = document.getElementById('f_dept').value;
    const examSelect = document.getElementById('exam_type');
    const arrivalInput = document.getElementById('arrival_time');
    const locSelect = document.getElementById('exam_location');

    if (dept === 'GASTRO') {
        const isGif = wakuName.includes('GIF');
        const isTcf = wakuName.includes('TCF');

        if (isGif) {
            if (!examSelect.value) examSelect.value = 'GIF';
            if (examSelect.value === 'GIF') {
                arrivalInput.value = calculateBefore30Min(wakuName);
            }
        }

        // GIF枠またはTCF枠の場合、実施場所は一番上の選択肢を選択（エコー枠等は未選択）
        if (isGif || isTcf) {
            if (locSelect && locSelect.options.length > 1) {
                locSelect.selectedIndex = 1;
            }
        } else {
            if (locSelect) {
                locSelect.value = '';
            }
        }
    }
}

5カレンダー選択セルの強調UI（2重線＆グラデーション）改善（month_schedule.php）

📌 課題とデザインアプローチ

月間カレンダー画面（month_schedule.php）において、多数の予約状況バッジや医師別集計が表示される中、現在どのカレンダーセルを選択しているかの視認性をさらに高めるデザイン調整を実施しました。

🎨 適用したCSSスタイル設計

  • 2重線アウトライン（レイアウト非破壊）:
    通常の border で太枠を指定するとセルのサイズや内部テーブルの余白が押し出されてレイアウト崩れが生じるため、outline: 3.5px double #033bb3ff !important; および outline-offset: -2px; を適用。外枠のみをくっきりと濃紺・青色の2重線で浮き立たせています。
  • 視認性を阻害しない淡いブルーグラデーション:
    セル背景に background: linear-gradient(to bottom, #ddeaffff 0%, #7bbbffff 100%); を指定。セル内部の文字情報（日付、各枠の予約数・空き数バッジ）の可読性を損なうことなく、選択セルであることが一目で判別できる質感を実現しました。

9【大型新設】内視鏡室 当日進捗ステータスモニター（電子ホワイトボード）の開発・リリース

1日の大腸内視鏡（CF・ポリペクトミー）が最大15名超まで増加する当院の内視鏡診療において、内視鏡室・前処置室・リカバリ室の「現在の患者動線」「マイトイレ空き状況」「検体照合・スコープ洗浄などの安全タスク」を看護師・補助看護師・受付事務・医師がリアルタイムに共有・監視できる「当日進捗ステータスモニター（電子ホワイトボード：progress_monitor.php）」を新規開発し、リリースしました。

💡 開発の背景と解決した現場課題

  • 複数職種にまたがる動線・タスクの分断: 受付事務（来院確認）、補助看護師（マイトイレ案内・下剤作成配薬・スコープ洗浄）、看護師（便チェック・検査介助・検体照合・リカバリ監視）、医師（検査・説明）が関わる複雑な動線を一元化。
  • 【重大インシデント未然防止】採取組織・個数の声出し照合: 生検やポリペクトミー実施時における検体部位（C/A/T/D/S/Rb/Ra/P等）の取り違いや採取個数ミスのインシデントを根絶するため、退室時の声出し照合モーダルを必須化。未照合時は画面全体で点滅警告。
  • スコープ洗浄指示の確実な伝達: 検査終了と同時に補助看護師へ洗浄指示タスク（指示中 ➔ 洗浄中 ➔ 完了）を自動発行し、伝達漏れによる機器不足を未然に防止。
  • 検査種別（CF vs GIF）とセデーション有無による動線分岐の吸収: 下剤を要しない胃カメラ（GIF）の前処置自動スキップや、鎮静剤なし時のリカバリ自動スキップをインテリジェントに制御。
  • 誤操作巻き戻し（Undo）の安全性: 現場の慌ただしい状況での誤タップに備え、理由選択付きで直前ステータスへ差し戻せるUndo機能と監査ログを完備。

      • 来院受付打刻の大型化: 未打刻の患者行に巨大なエメラルドボタン「🕒 来院受付 打刻」を提示。
      • 患者の現在所在をリアルタイム表示: 「📍 待合室」「🚽 マイトイレ」「🚪 検査待合」「🔬 内視鏡室」「🛏️ リカバリ室」「💬 診察室」「🏁 帰宅完了」の所在バッジを明示。
      • 会計帰宅完了直結: 結果説明済みの患者に「🚪 帰宅・完了 (会計済) ▶」を大きく提示。
      • 受付専用クイック絞り込み: 「📋 未受付 ＆ 会計待ちのみ絞り込む」トグル完備。
    • 職種専用テーマカラー ＆ インジケーターバー: テーブル直上のバーが各職種専用カラー（医師: エメラルド、看護師: インディゴ、補助: アンバー、受付: ティール、全体: スレート）に美しく切り替わり、現場リアルタイム人数とクイック絞り込みボタンを常設。
  • 自動更新タイマー ＆ クライアント個別保存 (localStorage): 10秒 / 20秒 / 30秒 / 60秒 / 停止 を切替可能（カウントダウンバー付き）。設定した更新秒数および選択した職種ビューはブラウザの localStorage に完全保存され、リロードや次回アクセス時も各端末（処置室iPad・受付PC・診察室端末・ナースステーション）ごとに最適な設定が永続維持される（ヘッダーに「💾 端末保存」バッジおよびトースト通知を常備）。

🎨 ポータル（index.php）カードデザイン全面改修 ＆ index.html リダイレクト

  • 白基調高コントラストデザインへの刷新: ポータル画面（index.php）に追加した電子ホワイトボードカードについて、初期の黒背景・コントラスト崩れを解消し、白ベース＋淡色アイスブルーグラデーション＋プライマリブルー枠線＋ダークスレート文字の高視認性デザインへ統一。
  • 7段階動線ステップパイプライン表示: カード内にカラーチップ列で動線フローを可視化し、主要現場機能タグ（職種別切替、GIFスキップ、セデーション連動、検体照合、Undo等）を整理して掲載。
  • index.html リダイレクト対応: ユーザーがブラウザで index.html にアクセスした場合でも即座に index.php へシームレス転送されるよう、ルートに index.html を配置。
