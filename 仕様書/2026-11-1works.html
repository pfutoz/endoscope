2. 空き枠検索（slot_search.php）カレンダー状況ホバープレビュー

【改修背景・現場の課題】
直近空き枠速報（大腸内視鏡）のカード一覧を閲覧している際、特定の空き枠について「この日は他の先生（胃腸科・肛門科）はどう埋まっているか？」「胃カメラやエコーの枠状況はどうなっているか？」を確認するために、毎回カレンダー画面へ画面遷移（ページジャンプ）する必要がありました。

【解決策と実装内容】
カード下部の「📅 カレンダー表示」ボタンにマウスカーソルを乗せる（ホバーする）だけで、画面遷移することなく、その日のカレンダー状況（month_schedule.php の該当セルと完全同一の各医師消化/定員および全体枠集計・メモ・医師不在予定）がダーク系モダンフローティングツールチップとして待ち時間ゼロ（体感即時）でポップアップ表示される新機能を実装しました。

主要な仕様と特徴

  • 胃腸科・肛門科の上下2段完全表示: 該当日について「🔵 胃腸科」と「🟢 肛門科」の両セクションを並べて表示し、内視鏡室全体の混雑状況を直感的に俯瞰可能。

  • 科別全体集計バー: 各科の下部に 全体 🔵10/10 🟠2/2 🟢10/10 の集計バーを常設。
  • 付加情報（日別メモ・医師予定）の自動連動: 該当日に日別メモ（📝）や医師不在・休診予定（🙅🏼）がある場合は、下部にコンパクトに同時プレビュー。

2.2 条件指定検索パワーアップ ＆ 初期表示時検索不具合の完全解消

【改修背景・ユーザーからの指摘】
「初期表示のとき検索できない」「検索ボタンを押しても結果が表示されない」「複数医師を選択したい」というご要望および動作不具合への対応を実施しました。

【根本原因の分析】

  1. 医師予定パース時のWarningによるJSON構文破壊: lib/calendar_helper.php の getCalendarPreviewsForDates() 内で、整形済み医師予定のキー title を誤参照したため、PHP Warning (Undefined array key "title") が出力され、AjaxレスポンスのJSON先頭に混入してブラウザ側の await res.json() が SyntaxError で例外中断していました。
  2. 初期表示（mode=custom）時のSSR未実行: 従来は search_clicked=1 パラメータが存在しない初回アクセス時にサーバーサイドでの検索（SSR）が実行されず、結果セクションが非表示（display: none）のまま停止していました。
  3. フロントエンド初期化時の検索トリガー漏れ: DOMContentLoaded 時に currentSearchMode === 'custom' の自動検索分岐が存在せず、タブ切替時にもデータ未描画判定が不十分でした。
  4. 複数医師選択時の勝手な全解除バグ: initButtons() に存在した「選択数 == 全医師数」判定により、全医師を選択した瞬間に勝手に解除されて「全医師」ボタンに戻ってしまう動作がありました。

【実施した対策と機能強化】

  • PHP Warning の完全根絶: calendar_helper.php の配列参照を $ev['raw_title'] ?? ($ev['title'] ?? '') に是正し、純粋・正常な JSON を確実に返却するよう修正。
  • 初期表示時（mode=custom）のSSR自動検索対応: 画面を開いた初回表示（search_mode === 'custom'）でも、デフォルト条件（胃腸科、全医師、全種別、全曜日、本日〜2か月後末日）でサーバーサイド検索を即座に実行し、テーブル（325行）およびコンパクトカード（162件）を初期HTMLに完全描画。開いた瞬間に待ち時間ゼロで結果が表示されます。
  • 高密度コンパクトカード表示モードの追加: テーブル形式とカード形式を1クリックで切り替え可能（localStorage でユーザーの好みを永続記憶）。カード内の「📅 カレンダー」ボタンからも当日の枠状況ホバープレビューが連動。
  • 確実な自動検索トリガー: DOMContentLoaded 時および「🔍 条件指定検索」タブ切替時に、未描画であれば即座に Ajax 自動検索を呼び出す安全フォールバックを実装。条件変更時も 250ms デバウンスで自動検索＆検索ボタンPulse点滅アニメーション。
  • 複数医師選択ロジックの改善: 全員選択時の勝手な解除判定を完全撤廃。「全医師」から医師をクリックすると単独選択となり、別の医師をクリックすると複数医師がそのままアクティブを維持。0人になった場合のみ「全医師」に自動復帰する直感的なUIに改善。

2.3 進捗モニター（当日進捗ステータスモニター）UI大幅スリム化 ＆ コントロール統合

【改修背景・課題】
当日進捗ステータスモニター（progress_monitor.php）において、ヘッダー右側に機能ボタンが7個も並び画面幅を強く圧迫していたほか、「圧縮表示」「標準表示」といった分かりにくい文言が存在していました。また、2行目（検査種別タブ）と3行目（サマリーバー）で検査種別の件数表示が完全に重複しており、視認性・操作性の向上が求められていました。

【実施した6大統合・スリム化改修】

  1. ヘッダー右側ボタンのプルダウン集約（<select> ドロップダウン化）:
    「➕ 当日・緊急追加」「🛡️ アラートスキャン」「⚡ 直近空き枠速報」「🖨️ 当日印刷」「📅 月間カレンダー」「🏠 ポータルメニュー」の6ボタンを、1つのコンパクトなリストボックス 📂 その他メニュー ▾ に統合。選択時に即座に対象モーダル起動や画面遷移を実行し、自動的に初期表示に戻る安全設計を採用。ヘッダーの省スペース化を実現しました。
  2. 自動更新コントロールの洗練（🔄 今すぐ更新アイコン）:
    更新間隔プルダウン（10秒/30秒/60秒/停止）の直後に 🔄 アイコンボタンを配置。1クリックで即座に最新データを取得し、アニメーションとともにトースト通知を表示。
  3. 表示モード切替の2択化 ＆「圧縮」文言の完全撤廃:
    「圧縮」「標準」の言葉を完全になくし、[ 📋 テーブル ] と [ 🔲 タイル ] の2択に整理。テーブル表示時は常に高密度（圧縮）スタイル（view-mode-compact）をデフォルト適用し、1画面でより多くの患者状況を俯瞰できるように改善。
  4. 日付ステッパー内への「今日へ」ボタン内包:
    独立していた「本日に戻る」ボタンを日付ステッパー内に 今日へ リンクとして内包。本日表示時は「本日」バッジ、他日表示時は「今日へ」ボタンとしてスマートに切り替わります。
  5. 検査種別タブとサマリーの完全合体（重複バッジの撤廃）:
    2行目の検査種別タブ（🔬 全内視鏡、🟢 大腸系 (TCF)、🟣 浣腸CF、🔵 胃カメラ）内にリアルタイム件数バッジを直接表示。これにより、3行目サマリーバーにあった重複バッジ（TCF/浣腸/胃）を完全撤廃し、サマリーバーを動線ステータス（1〜7・未照合）に特化させました。
  6. 「6. 結果説明」ステータスの1枠統合（待○/中○）:
    従来の「🔔 説明待」と「6. 説明中」を1つの枠 6. 説明 (待○/中○) に統合。枠をクリックした際の絞り込みも、説明待ちと説明中の両方を漏れなく抽出するように連動させました。

2.4 デイリーノート（schedule_note.php）日付バー大幅スリム化 ＆ ピッカー一本化

【改修背景・課題】
デイリーノート画面（schedule_note.php）の日付ナビゲーションバーにおいて、中央に大きな日付文字（📅 2026年11月1日 (日)）が表示されているすぐ右隣に、ほぼ同一の日付を示すピッカーボックス（[ 令和8年11/1 (日) 和暦 🗓️ ]）が並んでおり、日付表示が2重化して画面幅を無駄に圧迫していました。また、左右のステッパーボタン（-7日/前日/前診療日、次診療日/翌日/+7日）が独立して横に広がり、視覚的な煩雑さを生んでいました。

【実施した3大統合・スリム化改修】

  1. 日付の2重表示を完全解消（ピッカー優先型に一本化）:
    重複していた左側の大きな日付文字を撤廃。西暦・和暦ワンクリック切替と特大Flatpickr起動が一体となった [ 令和8年11/1 (日) 和暦 🗓️ ] を中央のメイン日付表示として一本化しました。
  2. 中央コントロール群の高さ32pxツライチ統一:
    中央に並ぶ [ 日付ピッカーボックス ]、[ ⛔ 休診 / 🟢 診療日 ] バッジ、[ ⭐ 本日 / 📅 今日へ (T) ] ボタンの3要素を、すべて高さ32pxで美しく揃えて並列配置。上下のズレを完全になくし、整然とした外観を実現しました。
  3. 左右ステッパーのセグメント連結スリム化（横幅大幅圧縮）:
    過去側3ボタン（[ ◀◀ -7日 ↑ | ◀ 前日 ← | ◀ 前診療日 Shift+← ]）および未来側3ボタン（[ 次診療日 ▶ Shift+→ | 翌日 ▶ → | +7日 ▶▶ ↓ ]）の隙間をなくし、一体化した連結ボタングループ（Segmented Button Group）に成形。キーボードショートカット操作性を100%維持しながら、左右の横幅を大幅に圧縮しました。
