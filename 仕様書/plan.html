1. 開発計画の背景と基本方針

内視鏡予約管理システム（Modernized Edition）は、予約マトリクス、月間カレンダー（日別メモ連携・出勤例外完全連動）、診療科別初期値制御、空き枠検索アルゴリズムの是正等を経て、予約・枠管理の基本機能群をすべて完備し、安定稼働フェーズへ移行しました。
本計画書は、さらなる「内視鏡室の現場DX」「医療事故ゼロ化」「システム保全（BCP）」「患者・窓口サービス向上」に向けた次期開発項目とアーキテクチャ方針を整理したものです。

🎯 中核方針（コア・コンセプト）
  • 「予約予定」から「当日現場動線」への拡張: 確定した予約データをモダリティ機器や内視鏡室モニターへ直接繋ぎ、現場スタッフの手作業・二重入力を徹底排除。
  • 強固な医療安全とセーフティネット: 抗血栓薬の休薬確認や感染症対策をシステム側でアシストし、万が一の誤操作（誤削除・誤移動）に対するUndo復元機能を担保。
  • 責務分離（SoC）とBCPの確立: DBバックアップ・リストアなどの基盤保全は、Web予約システムから切り離して独立運用し、単一障害点（SPOF）を排除。

2. 計画① 医用画像モダリティ 撮影オーダー連携 (DICOM MWL)

📡 内視鏡・超音波機器への撮影オーダー自動配信 DICOM/dicom_plan.html / Python中継サーバー
連携計画策定済

予約システムに確定登録された当日患者データを、内視鏡プロセッサ（富士フイルム ELUXEO / LASEREO、オリンパス等）や超音波診断装置（US）へ DICOM Modality Worklist (MWL) を介して自動配信する仕組みを構築します。

📌 目的と現場メリット
  • 患者取り違え事故の根絶: カルテ番号、患者氏名（漢字・カナ）、生年月日、性別が機器画面に自動提示され、検査開始前の手入力ミスや取り違えを防止。
  • 検査室スタッフの負担軽減: 検査直前にプロセッサへ患者情報を打ち込む作業時間をゼロ化し、迅速な検査導入を実現。
🏗️ システム構成アーキテクチャ
[ 予約システム (PostgreSQL) ] │ (当日予約の確定・変更) ▼ [ PHP オーダー連携API / JSON生成 ] ──(REST / JSON)──> [ Python DICOM MWLサーバー ] ・api_dicom_orders.php (常駐プロセス: mwl_server.py) ・場所別 (本館/新/おの) フィルタリング (pydicom / pynetdicom) │ (DICOM C-FIND 応答) ▼ [ 各検査機器・モダリティ ] ・内視鏡室 (富士 / オリンパス) [Modality: ES] ・超音波室 (エコー装置) [Modality: US]
⚙️ 実装ステップと設計要件
  • ステップ1（PHP側）: 当日の予約情報を取得し、DICOM規格に必要な属性（PatientID, PatientName, BirthDate, Sex, AccessionNumber, Modality, ScheduledProcedureStepStartDate）を出力するAPIエンドポイント（api/dicom_orders.php）を開発。
  • ステップ2（検査場所とAE Titleの連動）: 予約の「実施場所」（内視鏡室・内視鏡室新・内視鏡室おの）に応じて、対象端末のAE Title（Application Entity Title）をマッピングし、不要なオーダーの混入を防止。
  • ステップ3（Python MWLサーバー連携）: DICOM/dicom_plan.html に策定された mwl_server.py を院内サーバーに常駐サービス化（Windows Service または タスクスケジューラ常駐）。

3. 計画② 院内総合データベース・リストアシステム（独立運用）

🛡️ 全DB一括バックアップ連携 ＆ 3段階リストアシステム 独立運用ツール / PowerShell GUI / BCP対策
運用設計フェーズ

日次自動バックアップスクリプトにより C:\dbbackup\YYYYMMDD に保存されている 00_globals.sql および各DBの .dump（-Fc カスタム形式）を安全かつ迅速に復元するため、Web予約システム本体から完全に切り離された独立総合リストアツール を構築します。

💡 なぜWeb予約システムと切り離すのか？（アーキテクチャ上の必然性）
DB破損やApache障害などの緊急時、Webシステム内に復元機能があると「管理画面が開けずリストアを実行できない」というデッドロックに陥ります。他システム（電子カルテ関連等）も含めた共通インフラとして独立ツール化することが医療情報システムのベストプラクティスです。
⚙️ 総合リストアシステムの必須機能要件
機能項目 実装仕様・アプローチ 現場効果・安全設計
1. セッション強制切断
(セッションKick)		 リストア対象DBに対し、実行前に pg_terminate_backend(pid) を発行し、稼働中の全クライアント接続を切断。 「他ユーザーがアクセス中」によるリストア処理のロック・失敗を100%回避。
2. 3段階の復旧モード ・全損復旧: 00_globals.sql ➔ 全DB順次展開
・単一DB復元: 対象DBのみ選択して上書き復元
・テーブル単位救済: pg_restore -t [テーブル名] 		サーバー交換時の全復旧だけでなく、「予約テーブルだけ誤って消した」等の局所インシデントにも最小限の巻き戻しで対応可能。
3. 検証用DBへの
事前テストリストア		 本番DBへ直ちに上書きせず、一時DB（例: restore_test_db）へリストアしてデータ件数・最新日付を確認するモード。 リストア日付の選択ミスによる「正常な本番データを過去データで上書きしてしまう事故」を未然に防止。
💻 コア・コマンドライン仕様（PowerShell / pg_restore）
# 1. 接続セッション強制切断 & "$pgBinPath\psql.exe" -U $dbUser -d postgres -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname = '$targetDb' AND pid <> pg_backend_pid();" # 2. 単一DBクリーンリストア (-Fc 形式) & "$pgBinPath\pg_restore.exe" -U $dbUser -d $targetDb --clean --if-exists -v "$dumpFilePath" # 3. 特定テーブルのみのピンポイント救済（例: t_schedule のみ復元） & "$pgBinPath\pg_restore.exe" -U $dbUser -d $targetDb -t t_schedule "$dumpFilePath"

  • 医師指名（カラーコード ＆ ワンタップ切替）: 患者の「〇〇先生に検査してほしい」という指名希望に即応できるよう、各医師のパーソナルカラーバッジ（誠吾: 🟢 / 哲也: 🔵 / 義智: 🟣 / 慶太郎: 🟠）を表示。[全医師] [誠吾] [哲也] [義智] [慶太郎] のワンタップ切り替えで即座に絞り込み可能。
  • 枠が埋まり次第の即時自動消滅: 誰かが予約を入れて空き枠残数が0になった瞬間、全端末の画面から即座に自動非表示化（二重案内・重複ブッキングを100%防止）。
  • 診療科をまたぐワンクリック即予約: 肛門科カレンダーを開いていても、胃腸科の空き枠カードからワンクリックで該当科・該当日の予約入力モーダルが直接起動（open_new=1 連動）。
2. 院内多職種での共用動線（医師・看護師・受付）
  • 👨‍⚕️ 診察室の医師（外来診察中）: 「大腸カメラを最短いつ受けられるか」を診察室PCから0秒で把握し、その場で即決前倒し予約。
  • 👩‍⚕️ 外来・処置室の看護師: 患者からの「できるだけ早く受けたい」という相談に対し、直近速報を見て即座に日程提案。
  • 🧑‍🔬 内視鏡室スタッフ（ホワイトボード連動）: 当日進捗モニター上で直近枠の空き状況をリアルタイム把握し、急患や追加検査の受け入れ可否をスムーズに判断。
  • 💼 受付事務: 電話受付や会計時の次回予約案内において、最短枠や医師指名枠を保留時間ゼロでサジェスト。
3. 詳細空き枠検索（slot_search.php）とのタブ切替型完全統合
  • タブ切替型リニューアル（デフォルト直近速報モード）: 従来の「空き枠検索（slot_search.php）」を開くと、デフォルトで「⚡ 直近空き枠速報（全科横断・30日大腸CF）」が自動展開。「🔍 条件指定検索」タブで月別・曜日別・胃カメラ等のフル検索へ即座に切替可能。
  • 即応ウィジェットと詳細検索の連携: カレンダーやホワイトボードの常設ウィジェットで直近1か月を即答しつつ、「1か月以上先の日程」や「土曜日午前のみ等の特定条件」で探したい場合は、ワンクリックで条件を引き継いで詳細空き枠検索へ遷移。
  • 検索エンジンの共通化: lib/slot_helper.php の定員・枠計算ロジックを共通利用し、計算結果の完全一致と保守性を担保。
4. 患者控え伝票への「前処置ガイドQRコード」自動印字（Phase 4 残課題）
  • QRコード自動差し込み: print_patient_slip.php（患者控え伝票）に、検査種別に応じた案内用QRコードを自動印字。
  • 自宅での安心サポート: スマートフォンで読み取ることで、クリニック公式Webの「大腸内視鏡の下剤の飲み方解説動画」や「胃カメラ前日の食事制限・服薬ガイド」へ直接アクセス可能。
