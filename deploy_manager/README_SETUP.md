# 医療法人小野会 院内システム総合デプロイマネージャー
## システム環境前提条件・セットアップ ＆ トラブルシューティング手順書

本ツールは、ローカル開発環境（`c:\Apache24\htdocs\`）の変更差分を自動検知し、本番サーバー（`192.168.1.16`）へ**「安全な全自動事前ZIPバックアップ」**を取得した上でワンクリック配布（デプロイ）および即時ロールバック（復元）を行う院内統合デプロイシステムです。

---

## 1. システム構成と前提条件（重要）

```
[開発用PC (Windows)]
  │
  ├─ ブラウザ (UI画面)
  │     http://localhost/deploy_manager/  (ポート80 / Apache)
  │     または http://localhost:5050/
  │
  ├─ ローカルソースコード: c:\Apache24\htdocs\<各システム>\
  ├─ 事前バックアップ保存先: c:\deploy_backups\<各システム>\
  │
  └─ 支援サーバー (server.js / Node.js ポート5050) 【一般ユーザー権限】
        │
        │ [ネットワーク接続: T:ドライブ (SMB共有)]
        ▼
[本番サーバー (192.168.1.16)]
  └─ 本番ソースコード: c:\Apache24\htdocs\<各システム>\
```

### 【必須前提条件1】本番サーバー htdocs が「T:」ドライブとして共有されていること
- **本番サーバーIP**: `192.168.1.16`
- **本番共有フォルダ**: `\\192.168.1.16\c$\Apache24\htdocs`（または `\\192.168.1.16\htdocs`）
- **割り当てドライブ文字**: **`T:`**
- **理由**:
  本ツールは、本番環境のファイルを `T:\<system>\` として直接比較・事前ZIPバックアップ・上書きコピーします。そのため、エクスプローラーから `T:` ドライブとして常時アクセスできる必要があります。
- **設定注意点**:
  ネットワークドライブ割り当て時、必ず**「サインイン時に再接続する」**にチェックを入れ、パスワード資格情報を保存してください。

### 【必須前提条件2】Node.js 支援サーバー（ポート5050）が常駐していること
- **なぜ Apache (PHP) ではなく Node.js が必要なのか？**:
  ローカルの Apache は Windows サービスとして **`NT AUTHORITY\SYSTEM`（システム特殊アカウント）** で稼働しています。Windowsのセキュリティ仕様上、SYSTEMアカウントはネットワーク共有（`T:` や `\\192.168.1.16`）へのアクセスがブロックされます。
  そのため、Windowsにログインしている **一般ユーザー（Owner）権限** で動作する Node.js（ポート5050）が本番サーバーとの安全な通信の役割を担っています。

### 【必須前提条件3】Node.js のインストール
- Windows標準環境に加え、**Node.js (LTS版)** がインストールされている必要があります（外部パッケージ `npm install` 等は一切不要、標準機能のみで動作します）。

## 2. PC交換・OS再インストール時の復旧手順（完全3ステップ）

もしPCの故障、買い替え、OSのクリーン再インストール等を行った場合は、以下の **3ステップ** だけで元の通り完全に復旧します。

### ステップ1: Node.js のインストール
1. ブラウザで [Node.js 公式サイト (nodejs.org)](https://nodejs.org/) を開き、「LTS（推奨版）」のインストーラー（.msi）をダウンロードして実行します。
2. すべてデフォルト（Next連打）のまま完了させてください。

### ステップ2: 本番サーバーを「T:ドライブ」として割り当て
1. Windowsエクスプローラーを開き、左メニューの「PC」を右クリック ➔ **「ネットワークドライブの割り当て」** を選択します。
2. 以下の設定を入力します:
   - **ドライブ**: `T:`
   - **フォルダー**: `\\192.168.1.16\c$\Apache24\htdocs`（または `\\192.168.1.16\htdocs`）
   - **「サインイン時に再接続する」に必ずチェックを入れる**
3. 「完了」を押し、本番サーバーのユーザー名・パスワードを求められたら入力して「資格情報を記憶する」にチェックを入れます。
4. エクスプローラーで「T:」ドライブが開き、各システムのフォルダ（endoscope, op, karteview等）が見えることを確認します。

### ステップ3: デプロイマネージャーの自動常駐登録
1. `c:\Apache24\htdocs\deploy_manager\` フォルダを開きます。
2. **`register_startup.bat`** をダブルクリックして実行します。
3. これでWindowsスタートアップに登録され、次回以降のPC起動時にもバックグラウンドで自動常駐します。
4. ブラウザで `http://localhost/deploy_manager/`（またはデスクトップのショートカット）を開けば復旧完了です！

## 3. 付属バッチツール一覧

フォルダ内には以下の管理用バッチファイルが用意されています。

| ファイル名 | 用途・機能 |
|---|---|
| **`start_deploy_manager.bat`** | 通常起動スクリプト。ポート5050が未起動の場合は最小化バックグラウンドで起動し、ブラウザを開きます。 |
| **`register_startup.bat`** | Windows起動時の自動常駐スクリプト。PC起動と同時に自動でサーバーを裏で動かします（おすすめ）。 |
| **`unregister_startup.bat`** | 自動常駐の登録を解除するスクリプト。 |
| **`diagnostics.bat`** | コマンドプロンプト上で各接続要件（Node, ポート5050, Tドライブ, UNC等）を一発自己診断するツール。 |

## 4. トラブルシューティング（よくある症状と対策）

### Q1. 「システム一覧の取得に失敗しました: Failed to fetch」と赤字で表示される
- **原因**: ローカル支援サーバー（Node.js: ポート5050）が動いていません。
- **対策**:
  1. `start_deploy_manager.bat` をダブルクリックして起動してください。
  2. 毎回起動するのが面倒な場合は、`register_startup.bat` を実行してPC起動時自動常駐を設定してください。
  3. `diagnostics.bat` を実行すると、ポートやNodeの状態を即座に確認できます。

### Q2. 「⚠️ 本番サーバー (192.168.1.16) 未接続」と表示される
- **原因**: 本番サーバーの電源が落ちているか、LAN接続が切れているか、または「T:」ドライブのマウントが外れています。
- **対策**:
  1. エクスプローラーを開き、「T:」ドライブをクリックして中身が表示できるか確認してください。
  2. 赤い✕マークが付いている場合は、ダブルクリックして再接続（必要に応じてパスワード入力）してください。
  3. 本番PC（192.168.1.16）の電源が入っており、同一の院内LANに接続されているかご確認ください。

### Q3. デプロイしたファイルを以前の状態に戻したい（ロールバック）
- **手順**:
  1. 画面上部のタブから **「🕒 過去バックアップ ＆ ロールバック」** を開きます。
  2. 対象日時のバックアップZIP（配布実行時に全自動生成されています）の横にある **「⏪ この時点へ復元」** ボタンを押します。
  3. 確認ダイアログで「OK」を押すと、本番環境の該当ファイルが自動的にその時点の状態へ上書き復元されます。
